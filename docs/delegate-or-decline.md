# Delegate or Decline

Bandwidth is a constant constraint, not a problem to solve once — everyone runs out of it, regardless of how good the system is. So this flow runs two ways:

- **Reactive:** Jenn brings Proteus a specific task, request, or meeting invite ("should I take this on," "who should own this," "do I need to be in this") and it works through the flow below rather than just handing back an opinion.
- **Proactive — regular workload curation:** at the Weekly Review (`daily-work-companion.md` → Weekly), this same flow runs across the *current to-do list*, not just new asks as they land. GTD's Weekly Review already reclarifies whether each open item is still actionable; while doing that pass, also run each item through steps 2-4 below. This is the direct application of The ONE Thing's Focusing Question at the workload level: deciding what's no longer worth Jenn's bandwidth is as much a part of "the ONE thing" as deciding what is.

Synthesizes what's already been curated from the Time Management one-pagers (see `daily-work-companion.md` and `framework-nuggets.md`) into one usable process instead of Jenn having to remember which book said what.

## The flow

**1. Name it concretely.** What's actually being asked, and by whom? Vague framing ("I have too much on my plate") doesn't get a real answer — a specific task does.

**2. Does it play to a genuine strength?** (168 Hours, Laura Vanderkam / HBR's 10 Must Reads Vol. 2) Is this one of the 2-3 things Jenn is genuinely best at, or does someone else's strength fit it better? A task that's a strength match is worth more scrutiny before delegating; a mismatch is a strong candidate to delegate or outsource regardless of anything else below.

**3. Tag it.** (Eat That Frog, Brian Tracy — the ABCDE method) A, serious consequences if not done. B, should do, mild consequences. C, nice to do, no consequences. D, delegate. E, eliminate. If it's already a D or E, the decision is close to made — steps 4-5 are about *how*, not *whether*. Algorithms to Live By adds a time-based lens worth checking alongside the priority-based tag: tackling the soonest-due or quickest task first reduces overall lateness across everything on the list, and sometimes deliberately dropping a task (its own case for E) beats doing everything on the list poorly.

**4. Check actual capacity before deciding on strength/tag alone.** (Making Work Visible, Dominica DeGrandis) Newport/DeGrandis's 80% utilization trap: pushing past roughly 80% utilization causes queues and wait times to increase sharply. If Jenn's already near or over that, bias toward delegate/decline even for an A-tagged, strength-matched task — capacity is the constraint, not merit. Ask what's already in flight before adding one more thing, not after.

**5. Cross-check against her own operating principles.** Read the strategy/goals context in `.local/knowledge-index.md` — if it defines a rule about what's worth saying yes to (scope, influence, impact), apply it here explicitly rather than deciding on gut feel. This repo doesn't duplicate that content; it just means this step always runs.

**6. If the answer is decline — help execute it, not just decide it.** (The Art of Saying No / The Book of No)
- Default phrasing: "I don't," not "I can't" — a standing choice, not an obstacle to negotiate around.
- If it's on the spot and undecided: buy time ("let me check and get back to you") rather than answering reflexively.
- If this is a recurring category, check whether a standing blanket-no already exists from the quarterly trigger audit (`daily-work-companion.md` → Longer cadences → Quarterly) — if so, this decision is already made; if this is the second or third time a new category has come up, flag it as a candidate for the *next* quarterly audit instead of re-deciding from scratch each time. The reason a standing rule beats a case-by-case call: the **marginal-cost trap** (How Will You Measure Your Life, Clayton Christensen) — "just this once" thinking is how good intentions end up somewhere never intended, because holding a line 100% of the time is actually easier than holding it 98% of the time. A blanket-no removes the renegotiation, not just the decision.
- If declining outright isn't right but doing it herself isn't either: name who it should go to instead, rather than leaving "delegate" as an unresolved verb — (Who Not How, Dan Sullivan/Benjamin Hardy) the actual reframe is asking "who can get this done" instead of "how will I get this done," which is what steps 2-4 above have already been building toward.

## What this isn't

Not a new standing cadence check — nothing here runs on a schedule. It's a reusable process Proteus applies whenever Jenn brings it a live decision, the same way `framework-nuggets.md` entries get offered when they fit, not recited on a timer.
